# Guía común de grabación

Preparar seis archivos de video separados. El total final debe ser 60:00: 05:00, 08:00, 10:00, 12:00, 15:00 y 10:00. Los tiempos del guion son puntos de edición, no una afirmación de duración de videos ya grabados.

1. Abrir en el navegador el material de diapositivas y el editor asignado. Tener listos el archivo inicial, el ejemplo y la solución, cada uno por separado. Mostrar un único Main.java activo; nunca pegar varios programas Main juntos.
2. Cerrar pestañas y notificaciones personales. Ajustar el editor a texto legible (aproximadamente 20–24 px) y grabar a 1920×1080 si el equipo lo permite. Mostrar consola y código sin recortar líneas.
3. En la herramienta de grabación disponible, seleccionar pantalla o ventana y micrófono; hacer una prueba de 15 segundos y escucharla. Si no se dispone de grabador, usar uno web autorizado por el equipo; comprobar exportación MP4 gratuita antes de grabar la sesión completa. No se exige instalar software al alumnado.
4. Grabar cada bloque de un minuto siguiendo el guion. Narrar a ritmo natural, aproximadamente 115–135 palabras/minuto durante la explicación y usar el resto para escribir, señalar y ejecutar. No acelerar la voz para cumplir el tiempo. Ensayar y ajustar las demostraciones a los puntos de corte.
5. En cada minuto: diapositiva 00–06 s; narración y demostración 06–48 s; observación de resultado/anotación 48–58 s; transición 58–60 s. Si la explicación necesita más, adelantar una acción durante la narración; no añadir temas ni minutos.
6. Las indicaciones «pausa el video» dejan unos segundos para leer; el tiempo que el alumno trabaje con el video pausado NO se suma a los 60 minutos publicados.
7. Añadir rótulos con conceptos, flechas sobre código y subtítulos revisados. No poner nombres, logos del equipo, presentaciones personales ni marcas de autor en el contenido educativo o código.
8. Editar silencios accidentales y errores de navegación. Conservar pausas de lectura y ejecución. Comprobar duración del MP4 exportado, audio sin saturación, tildes y legibilidad a pantalla completa.
9. Subir a YouTube con visibilidad No listado, comprobar reproducción con el enlace y registrar URL real, duración, fecha y responsable. No marcar como publicado hasta hacerlo.

## Ejecutar en cada editor

**Replit, L1/L2/L5:** abrir el proyecto Java de la lección desde su enlace cuando esté creado; iniciar sesión si lo exige; abrir Main.java en el explorador de archivos, reemplazar solo su contenido por el programa elegido y pulsar Run. Ver Console. Si no hay proyecto, el responsable debe crear uno Java desde las opciones de proyecto/plantilla disponibles, agregar Main.java y configurar ejecución Java. No usar generación automática para reemplazar el ejercicio. La interfaz actual puede variar; verificar el recorrido en ensayo. No prometer ejecución anónima: la guía actual de Replit solicita cuenta.

**JDoodle, L3:** abrir https://www.jdoodle.com/online-java-compiler, seleccionar Java, usar clase pública Main y archivo Main.java (si la configuración propone otra clase, ajustar el nombre de clase principal a Main). Pegar un programa, pulsar Execute o Run y revisar Output. No necesita datos de entrada. Si el contador no termina, pulsar Stop y revisar su actualización.

**OnlineGDB, L4:** abrir https://www.onlinegdb.com/online_java_compiler, comprobar Language: Java y Main.java. Pegar el ejemplo. Abrir el área Input/stdin y escribir Luna seguido de salto de línea; pulsar Run. En modo Interactive Console escribir Luna cuando aparezca la pregunta y presionar Enter. No dejar stdin vacío en ejecución por lotes.

**L6:** repasar en el mismo editor de la mascota; abrir las páginas de Oracle en otra pestaña. El cuestionario y la actividad de compartir son las actividades oficiales, no una nueva lección de instalación.

## Publicación pendiente de enlaces precargados

Crear una copia inicial y otra resuelta por lección de práctica. Compartir copia o enlace de lectura/ejecución, sin permisos de edición del original. En JDoodle utilizar Share y acceso a cualquier persona con el enlace; en OnlineGDB Share genera el enlace cuando el servicio lo permite; en Replit utilizar la opción de compartir/remix del proyecto. Si aparece un inicio de sesión, debe completarlo el titular. No seleccionar planes de pago ni publicar datos personales.

Abrir cada URL en sesión privada, comprobar que carga el código correcto, ejecutar y anotar si exige cuenta gratuita. Replit puede no cumplir la frase «no es necesario registrarse» del modelo de 2026; conservar el editor asignado y consultar al docente esa diferencia antes de distribuir el curso. No sustituir silenciosamente el editor. Un enlace a la portada NO es un ejercicio precargado.

La verificación local del paquete no equivale a pruebas en estos sitios. Registrar la prueba online real en enlaces-y-publicacion.csv.
